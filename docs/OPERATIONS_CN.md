# 运维

收不到邮件时按以下顺序检查：Cloudflare DNS/MX → Email Routing 和规则优先级 → 应用域名是否启用 → D1/原始邮件持久化 → 解析状态 → 当前 UI 筛选条件。收不到通知时检查：启用状态/revision → 邮件时创建的任务 → payload 是否就绪 → paused/expired 状态 → 最新 HTTP 错误 → 接收端签名和幂等日志。R2 未回收时检查：逻辑过期 → 最近一次 Cron → 删除错误/重试 → 原始邮件清理 → 未发布的 run 和备份。

状态页显示最近收件时间、解析和投递积压、失败数量、最早到期任务、最近调度/清理时间以及待删除对象数量。这些是应用估算值，不是账单数据，也不是持续 DNS 健康检查。

D1 备份不包含 R2 邮件正文。可恢复备份必须同时快照/导出两者，保留对象键，并在恢复后校验引用。恢复后不要自动重发历史 Webhook。服务保留策略无法删除已经投递到下游或写入独立备份的副本。

一次维护操作会运行与 Cron 相同的有界函数，不能接收 SQL、URL 或对象键。轮换 `ADMIN_PASSWORD` 可以修改浏览器登录密码，轮换 `ADMIN_API_TOKEN` 可以独立更新自动化凭据，轮换 `SESSION_SECRET` 会使所有浏览器会话失效；Webhook 密钥轮换需要接收端重叠过渡期。不要启用公开 `r2.dev` 访问。
